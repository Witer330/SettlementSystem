# MiMo Desktop 内测申请 · 字段5「描述一个你用 AI 做过、或最想用 MiMo Desktop 完成的项目/任务」

## 完整版(约 900 字,推荐)

我是经营一家小型工贸企业(几十名员工)的负责人,不是专业程序员,但习惯自己动手解决厂里的信息化问题。这个项目 SettlementSystem(结算系统)就是我用 AI 从零做出来的一套"工资核算 + 进销存"一体化软件:把工人计件工资核算、采购、销售、出入库、库存和应收应付打通到同一个系统里,替代了过去靠 Excel 和纸质单据来回对账的日子。

**用 AI 做了什么:**
1. 以"我提业务需求、AI 写实现"的方式结对开发:用 AI 编程助手(Claude Code 等)直接在本地代码库写前端(Vue 3 + Element Plus)与后端(Node.js + Express + Prisma + SQLite)的完整功能,已形成员工/部门/工种管理、产品/工序/BOM、计件报工与工资核算、生产工单、采购销售、出入库与库存查询、应收应付、仪表盘与多维报表等几十个页面,共 28 张业务数据表。
2. 又用 Tauri 2 + Rust 给它套上桌面壳,做成"双击即用、无需服务器、断网可用"的桌面程序,带开机自启、数据自动备份、OSS 在线自动更新与失败回滚(SHA256 校验)。
3. DeepSeek、豆包等对话模型当"业务顾问",帮我把复杂的计件工资算法(规格系数、工序单价、加班补贴、保底等)理清楚再落到数据库和计算公式里,排查报错。
4. 用 AI 把脑中零散的需求整理成需求文档、页面原型和 UI 设计规范,再照着实现。

**遇到过的主要问题:**
- 工资是"算错一个数都出事"的领域,计件规则又特别细。我要求 AI 动计算逻辑前先把业务规则和校验边界画清楚,关键路径加事务、逐条核算留痕,避免账实对不上。
- 需求是边用边改的,模块越加越多,直接让 AI 改容易"牵一发动全身"。后来约定每次改动前先对存量代码做影响分析(确认会波及哪些调用方),再小步重构 + 回归,几十个功能就是在这样反复迭代中长出来的。
- 工厂现场网络差、没人懂运维,所以最终形态是"断网可用、更新不丢数据"的桌面版,代码托管在 GitHub:https://github.com/Wtier330/SettlementSystem

**最想用 MiMo Desktop 完成的事:**
把这个"AI 结对开发"的模式再往前推一步——让 MiMo Desktop 成为我持续维护这套大型代码库的主力助手:直接读取本地整个项目、理解几十个模块的业务关系,帮我修 Bug、按新需求加功能、做重构,并自动跑类型检查与构建完成回归验证;大型任务交给多角色 Agent 协同拆解,长会话缓存也能显著降低反复维护的成本,恰好命中我"长期、大型、多模块"的真实场景。同时,厂里每天都在产生 Excel 工资表、报工单、往来对账这类素材,我很期待用 MiMo Desktop 的"可编辑交付成果"能力,把这些原始素材直接整理成规范表格与报表,甚至自动生成员工操作手册和培训材料。

我对 AI 的态度很朴素:工具越顺手,越能帮"不懂编程的小老板"把专业软件做到能用、敢用、长期用。希望获得 MiMo Desktop 内测资格,把它接入这条真实的生产链路里验证效果。

## 精简版(约 300 字,若表单有字数上限)

作为小工贸企业负责人,我用 AI 编程助手(Claude Code 等)从零开发了一套已在真实业务场景落地的"工资核算 + 进销存"结算系统,覆盖员工、计件报工、工资核算、采购销售、出入库、应收应付与报表,共 28 张业务数据表、几十个页面,并用 Tauri + Rust 做成断网可用的桌面版,支持自动备份与在线更新。过程中最大的难点是工资规则复杂、需求边用边改,我通过让 AI 每次改动前先做影响分析、小步重构并回归,确保不把账算错。代码托管在 GitHub:https://github.com/Wtier330/SettlementSystem。最想用 MiMo Desktop 把它作为主力助手继续维护:直接读取本地大型代码库修 Bug、加功能、重构并自动构建回归,用多 Agent 拆解长任务,并把工厂每天产生的 Excel/单据素材整理成可编辑的规范表格与报表。
