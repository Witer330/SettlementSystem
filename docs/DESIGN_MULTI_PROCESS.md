# 多维业务流程可视化设计方案

> 面向小工厂真实作业场景，将单线串行流程升级为并行、交叉、回环的多维流程图

---

## 一、场景调研：小工厂非线性作业用例

基于小工厂（10-100人、单设备多模具、一人多岗）的实际作业节拍，梳理以下典型场景：

### 1.1 并行工序场景

| # | 场景 | 说明 | 当前系统处理 |
|---|---|---|---|
| 1 | **并行生产** | 同一订单的多个产品在不同模具/设备上同时加工 | 仅支持单条报工记录 |
| 2 | **一人多岗** | 同一员工上午操作冲压机，下午转到装配线 | 员工只关联一个工种 |
| 3 | **跨部门协作** | 生产部完成半成品 → 仓库入库 → 质检 → 再出库加工 | 无跨部门流转节点 |

### 1.2 异常回退场景

| # | 场景 | 说明 | 当前系统处理 |
|---|---|---|---|
| 4 | **生产返工** | 产品不合格，需退回上道工序重新加工 | 无返工流程，只能删除重录 |
| 5 | **紧急插单** | 客户加急订单插入，需调整现有生产排程 | 无插单机制，手动调整顺序 |
| 6 | **补料申请** | 生产过程中原材料不足，需临时追加采购 | 采购单独立，与生产无关联 |
| 7 | **订单取消/变更** | 客户取消或修改订单，已生产的半成品需处理 | 无取消流程 |

### 1.3 数据交叉场景

| # | 场景 | 说明 | 当前系统处理 |
|---|---|---|---|
| 8 | **计件与出库差异** | 报工数量与实际出库数量不一致（损耗、废品） | 两个模块独立，无对比 |
| 9 | **工资与库存联动** | 计件工资基于报工数量，但废品不应计薪 | 工资直接取报工数 |
| 10 | **物料需求与采购时差** | 需求分析后采购有交期延迟，库存数据过时 | 无时间维度的库存预测 |

### 1.4 状态流转场景

| # | 场景 | 说明 | 当前系统处理 |
|---|---|---|---|
| 11 | **多级审批** | 大额采购需主管→财务→总经理逐级审批 | 无审批流程 |
| 12 | **质检拦截** | 入库前质检不合格，阻断后续流程 | 无质检节点 |

## 二、三层流程图结构设计

### 2.1 主流程（里程碑级）

只保留关键决策点和状态变更节点，用于首页和全局概览：

```
销售下单 → 物料需求分析 → 采购下单 → 原材料入库 → 生产出库 → 生产报工 → 成品入库 → 工资核算
```

### 2.2 子流程（并行分支）

在主流程每个节点下展开详细操作：

**生产报工子流程：**
```
领取原材料
  ├─ [并行] 模具A加工 → 自检 → 合格? → 是 → 入库
  │                      └─ 否 → 返工 → 重新加工
  ├─ [并行] 模具B加工 → 自检 → 合格? → 是 → 入库
  └─ [并行] 模具C加工 → 自检 → 合格? → 是 → 入库
```

**进销存子流程：**
```
销售订单
  ├─ 物料需求计算
  │   ├─ [库存充足] 直接出库
  │   └─ [库存不足] 采购申请 → 采购下单 → 到货入库 → 出库
  └─ 生产领料 → 生产加工 → 成品入库 → 发货
```

### 2.3 异常流程（回退/补救）

覆盖所有非正常路径：

```
异常类型          触发条件              处理流程
─────────────────────────────────────────────────
生产返工          质检不合格            返工单 → 重新报工 → 重新质检
紧急插单          客户加急              插单标记 → 调整排程 → 优先生产
补料申请          原材料不足            补料单 → 审批 → 紧急采购 → 入库 → 出库
订单变更          客户修改需求          变更单 → 评估影响 → 调整生产/采购
废品处理          不可返工的废品        报废单 → 库存扣减 → 成本核算
```

## 三、泳道图设计

### 3.1 横向泳道（按岗位/角色）

```
┌──────────┬──────────┬──────────┬──────────┬──────────┐
│  销售员   │  采购员   │  仓管员   │  生产工人  │  财务     │
├──────────┼──────────┼──────────┼──────────┼──────────┤
│ 录入订单  │          │          │          │          │
│          │ 分析需求  │          │          │          │
│          │ 下采购单  │ 入库登记  │          │          │
│          │          │          │ 领料出库  │          │
│          │          │          │ 生产报工  │          │
│          │          │ 成品入库  │          │          │
│          │          │          │          │ 工资核算  │
└──────────┴──────────┴──────────┴──────────┴──────────┘
```

### 3.2 状态颜色编码

| 颜色 | 状态 | 含义 |
|---|---|---|
| `#E5E7EB` 灰色 | 未开始 | 尚未触发的节点 |
| `#3B82F6` 蓝色 | 进行中 | 当前正在执行 |
| `#F59E0B` 黄色 | 预警 | 接近截止或库存临界 |
| `#EF4444` 红色 | 异常 | 出错、返工、缺料 |
| `#10B981` 绿色 | 已完成 | 正常完成 |

### 3.3 瓶颈识别规则

- 同一泳道内连续 3+ 个蓝色节点 → 该岗位可能过载，标黄
- 红色节点下游有灰色节点 → 流程阻塞，红色节点高亮闪烁
- 黄色节点持续 > 预设时间 → 自动升级为红色

## 四、交互功能设计

### 4.1 节点点击详情

点击任意节点，弹出该节点对应的系统单据信息：

```
┌─────────────────────────────┐
│ 生产报工 - 2026-05-09       │
├─────────────────────────────┤
│ 报工人：张三                 │
│ 产品：零件A (P-001)         │
│ 数量：500 件                │
│ 工时：4.5 小时              │
│ 状态：已提交                 │
│                             │
│ 关联单据：                   │
│  · 领料单 M-20260509-001    │
│  · 质检单 Q-20260509-001    │
│                             │
│ [查看报工单] [查看质检结果]   │
└─────────────────────────────┘
```

### 4.2 计件数据来源标识

工资核算泳道中，每个计件工人旁显示：

```
张三 - 计件工资 ¥2,450
  ├─ 报工数量：500 件 ← 生产报工
  ├─ 出库数量：520 件 ← 进销存
  └─ 差异：+4% ⚠️ 高亮提醒（阈值 ≥2%）
```

### 4.3 拖拽排序（后台配置用）

仅在系统设置的流程配置页面启用：
- 拖拽调整节点顺序
- 自动校验：不可将"入库"拖到"出库"之前
- 校验失败时节点抖动 + 提示文字

## 五、数据关联规则

### 5.1 计件 vs 出库差异检测

```
差异率 = |报工数量 - 出库数量| / 出库数量 × 100%

差异率 < 2%  → 正常（绿色标记）
差异率 2-5%  → 预警（黄色标记 + 提示）
差异率 > 5%  → 异常（红色标记 + 弹窗）
```

### 5.2 跨模块状态同步

| 事件 | 触发动作 | 目标模块 |
|---|---|---|
| 销售单确认 | 生成物料需求 | 进销存 |
| 采购入库完成 | 更新库存可用量 | 进销存 |
| 生产报工提交 | 扣减原材料库存 | 进销存 |
| 生产报工提交 | 累加计件数据 | 工资核算 |
| 成品入库完成 | 更新成品库存 | 进销存 |

## 六、实施路线图

### Phase 1：基础可视化（2 周）

- 首页流程图增加状态颜色（灰/蓝/绿）
- 各模块页面顶部添加状态进度条
- 节点点击弹出基础详情

### Phase 2：数据关联（2 周）

- 工资核算页面增加计件 vs 出库差异对比
- 采购与物料需求的数据联动
- 跨模块状态同步事件

### Phase 3：异常流程（3 周）

- 返工流程（报工 → 质检 → 不合格 → 返工单 → 重新报工）
- 紧急插单流程
- 补料申请流程

### Phase 4：泳道图（3 周）

- 横向泳道图组件（按岗位）
- 状态颜色编码
- 瓶颈自动识别

### Phase 5：高级交互（2 周）

- 拖拽排序（配置页面）
- 多条件分支配置
- 子流程折叠/展开

## 七、技术选型建议

| 能力 | 方案 | 理由 |
|---|---|---|
| 流程图渲染 | 纯 CSS Grid + Flexbox | 当前项目无需复杂拓扑，保持轻量 |
| 状态管理 | Pinia + Settings API | 复用现有架构 |
| 数据关联 | 后端聚合接口 | 避免前端多次请求 |
| 打印友好 | CSS `@media print` | 零依赖 |

**不建议引入的：**
- React Flow / AntV X6 — 项目是 Vue，引入 React 生态不合理
- bpmn-js — 过重，小工厂不需要 BPMN 标准
- Canvas 维护成本高，小屏幕兼容差

## 八、验收标准（可量化）

| 指标 | 目标值 |
|---|---|
| 流程图渲染（≤50 节点） | < 100ms |
| 节点点击响应 | < 200ms |
| 计件 vs 出库差异检测 | 实时计算 |
| 移动端适配 | 768px 以下垂直堆叠 |
| 打印输出 | A4 纸张完整显示 |
